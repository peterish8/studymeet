## Directory Purposes

**`convex/`:**
- Purpose: All server-side logic. Each file maps to a domain/feature and exports named `query` and `mutation` functions
- Contains: Domain modules, schema definition, auto-generated types
- Key files: `convex/schema.ts` (database contract), `convex/rooms.ts` (core room lifecycle)
- Note: `convex/_generated/` is auto-generated by the Convex CLI — never edit manually

**`src/app/`:**
- Purpose: Next.js App Router pages. Each subdirectory with a `page.tsx` becomes a route
- Contains: Route pages only — no business logic, no API routes. All data access goes through Convex hooks
- Key files: `src/app/layout.tsx` (root), `src/app/room/[id]/page.tsx` (primary feature page)

**`src/components/`:**
- Purpose: Reusable React components shared across pages
- Contains: Feature components (Whiteboard, VideoCall, Sidebar, etc.) and primitive UI components in `ui/`
- Key distinction: `src/components/ui/` holds design-system primitives (Button, Input, Card); `src/components/` holds feature components that own Convex subscriptions

**`src/lib/`:**
- Purpose: Framework-agnostic utility functions
- Contains: `utils.ts` (general helpers), `auth.ts` (localStorage identity helpers)
- Note: `convex/rooms.ts` imports `generateRoomCode` directly from `src/lib/utils` — this is intentional code sharing between layers

**`src/store/`:**
- Purpose: Client-side state management
- Contains: Single Zustand store file (`useStore.ts`)

**`public/`:**
- Purpose: Static assets served at root path
- Generated: No — manually managed

**`memory/`:**
- Purpose: Project planning docs (`project-brief.md`, `current-strategy.md`, `decisions.md`, etc.)
- Not application code — not imported by any source file

## Naming Conventions

**Files:**
- Pages: `page.tsx` (Next.js App Router convention — always `page.tsx`)
- Components: PascalCase matching the exported component name — `Whiteboard.tsx`, `VideoCall.tsx`
- UI primitives: PascalCase in `src/components/ui/` — `Button.tsx`, `ThemeToggle.tsx`
- Utilities: camelCase — `utils.ts`, `auth.ts`
- Convex modules: camelCase matching the domain noun — `rooms.ts`, `todos.ts`, `floatingNotes.ts`
- Store: camelCase with `use` prefix matching the exported hook — `useStore.ts`

**Directories:**
- App routes: lowercase kebab-case matching URL segment — `auth/callback/`, `room/[id]/`
- Component subdirectory: lowercase — `ui/`
- Source directories: lowercase — `app/`, `components/`, `lib/`, `store/`

**Exported Names:**
- React components: PascalCase — `export function VideoCall(...)`, `export default function RoomPage()`
- Convex functions: camelCase — `export const getByCode = query(...)`, `export const create = mutation(...)`
- Hooks: camelCase with `use` prefix — `export const useStore = create<AppState>()()`
- Utility functions: camelCase — `generateRoomCode`, `formatTime`, `cn`
- Types/Interfaces: PascalCase — `Theme`, `Tool`, `TodoMode`, `AppState`

## Where to Add New Code

**New Convex backend feature (query or mutation):**
- Create or extend a file in `convex/` named after the domain noun (e.g., `convex/polls.ts`)
- Add new tables to `convex/schema.ts`
- Run `npm run convex:dev` to regenerate `convex/_generated/`
- Import via `import { api } from "@/convex/_generated/api"` in the frontend

**New application page (new route):**
- Create `src/app/<route-name>/page.tsx`
- Add `"use client"` directive if the page uses hooks, Convex, or browser APIs
- The page is automatically available at `/<route-name>`

**New feature component:**
- Place in `src/components/<ComponentName>.tsx`
- If it's a design-system primitive with no Convex dependencies, place in `src/components/ui/<ComponentName>.tsx`

**New utility function:**
- If shared between frontend and Convex backend: add to `src/lib/utils.ts`
- If frontend-only identity/auth helper: add to `src/lib/auth.ts`

**New client-side state slice:**
- Extend the interface and initial state in `src/store/useStore.ts`
- Add setter/toggle functions to the `create` call
- Only persist to localStorage (via `partialize`) if the value must survive page refresh

## Special Directories

**`convex/_generated/`:**
- Purpose: Auto-generated TypeScript types and JavaScript module for the Convex API
- Generated: Yes — by `npx convex dev` / `npm run convex:dev`
- Committed: Yes (Convex projects typically commit generated files)
- Never edit manually — changes will be overwritten

**`.next/`:**
- Purpose: Next.js build output and cache
- Generated: Yes — by `next build` / `next dev`
- Committed: No (gitignored)

**`.planning/`:**
- Purpose: GSD planning documents (phases, codebase analysis)
- Generated: Yes — by GSD commands
- Committed: Up to team preference

**`memory/`:**
- Purpose: Human-readable project context docs for AI-assisted development
- Generated: No — manually maintained
- Committed: Yes
